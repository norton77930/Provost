# Matt-style skill workflow guidance

Follow actual installed skills and project memory. A possible flow is grill-me ?
PRD ? issues or local tasks ? approved implementation slice ? review/verify ?
handoff. Do not recreate approved upstream work on every continuation.

Keep complete identities: local path and item, GitHub URL and issue, or GitLab URL
and issue. Equal numbers across providers/projects are different tasks. Honor
Blocked by; unknown dependencies are not none. Even tickets without paths need a
brief specifying acceptance, write scope and shared resources before dispatch.

Closed tickets and old handoffs are not acceptance evidence. Check code/evidence
and worker state. Remove completed/cancelled items from new pending summaries;
retain superseded decision references in immutable history. Resolve factual gaps;
ask for product decisions, expanded scope or ambiguous continuation candidates.

No automatic issue closure, PR/MR creation, publishing, worktree or commit follows
from handoff. This guide defines Provost behavior; it does not claim Matt's skills
provide Provost history, automatic expiry, or compaction hooks.
