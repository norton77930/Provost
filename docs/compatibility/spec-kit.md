# spec-kit source guidance

Use explicit task sources first, then project memory. Identify the intended feature;
with two plausible features, clarify before dispatch. Read its spec, plan, tasks,
checklists and constitution. Unmet native quality gates remain binding.

[P] is a parallel candidate, not permission. Check dependencies, interfaces, file
ownership and shared resources; project single-writer rules win. Group coherent
RED/GREEN tasks into a bounded brief. Workers never own the whole implement loop.
Main updates common progress. Convergence may add tasks for approved acceptance,
not expand requirements. Do not rewrite feature metadata to adapt to Provost.

Inspect installed workflow outputs and actual source files; there is no fixed
parser. Checkpoints reference sources and do not replace acceptance evidence.
